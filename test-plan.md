1. Project Overview

This project focuses on planning manual functional testing for the SauceDemo e-commerce web application.

SauceDemo is a demonstration shopping website that lets users log in, browse products, sort inventory, add or remove items from their shopping cart, and complete checkout.

The purpose of this test plan is to define the testing objectives, scope, environment, and conditions required before and after test execution.

 2. Test Objective

To verify that users can successfully:

- Log in to the application using valid credentials.
- Browse available products.
- Sort products using the available sorting options.
- Add products to the shopping cart.
- Remove products from the shopping cart.
- Complete the checkout process successfully.

3. Testing Scope

3.1 In Scope

The following functionalities are included in the testing plan:

Login Functionality
- Verify successful login using valid credentials.
- Verify the application's response to invalid login credentials.

Product Browsing and Sorting
- Verify that products are displayed correctly.
- Verify that available product sorting options work as expected.

Shopping Car
- Verify that users can add products to the cart.
- Verify that users can remove products from the cart.
- Verify that the cart reflects changes made by the user.

Checkout Process
- Verify that users can proceed to checkout.
- Verify that required checkout information is validated.
- Verify that users can complete the checkout process.

 3.2 Out of Scope

The following activities are excluded from this testing plan:

- Automated testing.
- Performance and load testing.
- Security penetration testing.
- Testing unsupported product quantity controls.

 5. Entry Criteria

Testing can begin when the following conditions are met:

1. The SauceDemo website is accessible.
2. Valid test credentials are available.
3. The testing environment is ready.
4. The planned test scenarios have been identified.

 6. Exit Criteria

Testing will be considered complete when:

1. All planned test cases have been executed.
2. Test execution results have been documented.
3. All identified critical defects have been resolved and retested.
4. Any unresolved defects have been documented and communicated.
5. A test summary has been prepared.

7. Testing Approach

Manual functional testing will be used to verify the application's main features.

Testing will focus on comparing actual application behaviour against expected results.

The planned process includes:

1. Review the application.
2. Identify test scenarios.
3. Design test cases.
4. Execute test cases manually.
5. Record actual results.
6. Report defects where applicable.
7. Retest resolved defects.
8. Document the final testing results.

8. Risks and Considerations

Potential risks include:

- Website unavailability during testing.
- Issues with test credentials.
- Unexpected application behaviour.
- Browser-specific issues.
- Limited time for test execution.

9. Deliverables

The following documents are planned for this project:

- Manual Test Plan
- Test Cases
- Test Execution Results
- Bug Reports (if defects are identified)
- Test Summary Report
